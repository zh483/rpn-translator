# Day 06 任务卡 · Evaluator：后缀序列求值

> **时间盒 60–75 分钟**。输入是 Parser 产出的**后缀序 `List<Token>`**，输出是一个 `double`。
> 一句话：一个操作数栈，从左到右扫，遇数压栈、遇运算符弹两个算完压回。

## 一、目标与签名

```java
public class Evaluator {
    /**
     * 对后缀序记号序列求值。
     *
     * @param rpn 后缀序记号序列（由 Parser 产出）
     * @return 计算结果
     * @throws CompileException 运行时错误（除数为零、序列不完整等），带字符位置
     */
    public double eval(List<Token> rpn) { ... }
}
```

内部只需一个栈：`Deque<Double> stack = new ArrayDeque<>();`（ADR-003 定的结构）。

## 二、每个记号怎么处理

| 记号类型 | 动作 |
|---|---|
| `NUM` | `stack.push(t.value())` ← 直接用词法阶段存好的数值，不用再解析文本 |
| `NEG` | `stack.push(-stack.pop())` ← 一元负号，只弹 1 个 |
| `PLUS` / `MINUS` / `STAR` / `SLASH` / `PERCENT` | **先弹右、再弹左**（顺序反过来减法和除法就错了），算完压回 |
| 其它（`LPAREN`/`RPAREN`/`EOF`） | 不该出现在后缀序列里 → 内部错误 |

`switch (t.type())` 用箭头形式即可；`NEG` 和二元分支必须分开写。

## 三、三个错误检查（都要带位置）

1. **除数为零**（`/` 与 `%` 都算）：抛 `CompileException(Kind.RUNTIME, t.pos(), "除数为零")`
2. **弹栈时栈不够**：说明后缀序列不合法（正常流程不会出现），抛 `Kind.RUNTIME` + "表达式不完整"
3. **结束时栈里不是恰好 1 个元素**：同样按内部错误处理

位置用 `t.pos()`（运算符在原串里的字符位置）——这就是选 `List<Token>` 做中间表示的好处：**运行时错误也能定位到源码字符**。

## 四、数值格式化（单独一个小类，别塞进 Evaluator）

`ResultFormatter.format(double)`：

- 与整数差值 `< 1e-9` → 输出整数形式（`7.0` → `7`）
- 否则最多 10 位有效数字并去尾零（`String.format("%.10g", v)` 大致可满足）
- 边界：`0.1 + 0.2` 在二进制浮点里是 `0.30000000000000004`，格式化后必须显示 `0.3`

**Evaluator 只返回 `double`，格式化是展示层的事**——这样测试断言可以直接比数值（带容差），界面显示才调 formatter。

## 五、验收用例（10 条数值 + 2 条运行时错误）

| # | 输入表达式 | 期望结果 | 覆盖点 |
| --- | --- | --- | --- |
| V01 | `1+2*3` | `7` | 优先级 |
| V02 | `(1+2)*3` | `9` | 括号 |
| V03 | `1-2-3` | `-4` | 左结合 |
| V04 | `8/4/2` | `1` | 左结合（除法） |
| V05 | `2.5+0.5` | `3` | 浮点后取整 |
| V06 | `7%3` | `1` | 取模 |
| V07 | `-7%3` | `-1` | 取模符号随被除数（Java 语义） |
| V08 | `-2*3` | `-6` | 一元负号 `NEG` |
| V09 | `2--3` | `5` | 一元负号在二元减号后 |
| V10 | `(1+2)*(3-4)` | `-3` | 组合 |
| R01 | `8/(2-2)` | 运行时错误：除数为零 | `/` 除零 |
| R02 | `7%(3-3)` | 运行时错误：除数为零 | `%` 除零 |

数值比较用容差：`Math.abs(actual - expected) < 1e-9`。

另外单独测 3 条格式化：`7.0→"7"`、`3.5→"3.5"`、`0.1+0.2→"0.3"`。
