# 架构决策记录（ADR）

> 每条决策只回答三件事：**背景**、**选择**、**代价**。改主意时不要偷偷改代码，先改这个文件。

## ADR-001 语言与工具链：Java 25 LTS + 裸 javac

**背景**：课程推荐 C++/Java；目标之一是借课设学 Java；机器原环境 `JAVA_HOME` 指向已删除的 jdk-25，实际只有 jdk-1.8/17。
**选择**：装 Microsoft OpenJDK 25 LTS；不用 Maven/Gradle；`javac -encoding UTF-8 -d out\classes src\rpn\*.java` + `run.bat`。
**代价**：没有依赖管理与 JUnit；换来的是零网络依赖、双击可运行、验收现场最可靠。JDK 25 的 `record`/`switch` 表达式够用且能写进报告。

## ADR-002 翻译方案：递归下降 + 综合属性

**背景**：要求明确"必须实现属性文法中的语义动作"；同时允许算符优先。原始文法 `E→E+T|T` 左递归。
**选择**：先消左递归得 `E→TE'`、`E'→+TE'|ε`；每个非终结符设综合属性 `postfix`（后缀串），方法返回值即属性值。
**代价**：不能用继承属性（本项目不需要）；换来的是"翻译与语法分析一遍完成"，报告中"为什么消左递归后综合属性仍成立"是答辩加分点。

## ADR-003 数值：内部统一 double + 输出格式化

**背景**：要求识别整数与浮点；`%` 对浮点、除零、`0.1+0.2` 的尾数误差都需要定义。
**选择**：词法区分 int/float 两类 token（报告要体现识别能力），但统一解析为 `double`；输出规则为"与整数相差 <1e-9 打印整数，否则最多 10 位有效数字并去尾零"；除零/取模零 → 运行时错误。
**代价**：不接受 BigDecimal 的精确小数；换来的是 45 小时预算内可控的实现与错误处理。

## ADR-004 一元负号：后缀式中用专用记号 `neg`

**背景**：`-3` 与 `a-b` 在后缀式中都表现为 `-`，求值器无法区分一元/二元。
**选择**：`F → '-' F` 的语义动作输出 `neg`；求值器遇 `neg` 弹 1 个操作数取负。
**代价**：后缀式与"纯教材写法"不完全一致；换来的是求值器无歧义，且报告里能讲清"为什么需要引入新记号"。

## ADR-005 界面：一核两壳（Web 主 + Swing 壳），前端用原生 JS 零构建

**背景**：要求"图形界面"；本人想借机练前端；前端基础为零；答辩用自己电脑。
**选择**：核心 `RpnService` 不含界面依赖；主界面为浏览器单页（手写 HTML/CSS/JS，`fetch` 调 `WebApi`，JSON 协议）；备用壳 `SwingShell` 直接调用 `RpnService`，保证"桌面程序"形态可现场演示。
**代价**：多维护一个接口层（约 90 行）；换来的是分层清晰、可现场切换、报告可写"一核两壳"。**不用 TS**：`tsc` 引入构建步骤，违背"双击即跑"；等验收后想迁移再迁。

## ADR-006 错误模型：首错即停 + 类别/位置/期望集

**背景**：要求指出错误位置并给出可读信息。
**选择**：统一 `CompileException(kind, pos, message, expected)`；`expect()` 负责抛出；界面显示类别、位置、期望集，并在等宽行用 `^` 指示。
**消息格式锁定**：`[词法错误] 第 2 个字符: 非法字符 '$'` —— 方括号内是类别，位置按 1 基显示，**半角冒号 + 一个空格**。报告与程序必须逐字一致（报告引用一律复制真实输出，不手打）。
**代价**：不做多错误恢复（写进"展望"）；换来的是单行表达式场景下最简单的正确实现。

## ADR-007 报告流水线：Markdown 单一事实源 → docx 渲染

**背景**：模板对字体/字号/行距/图表编号有硬性要求；报告一已验证 python-docx 路线。
**选择**：只维护 `report/草稿-报告二.md`，用 `tools/md2docx.py` 以**老师模板文件为基底**渲染；生成后自动校验字体字号、图表连号、正文引用。
**代价**：复杂表格/公式需扩展转换器；换来的是"改内容不改格式"、格式错误机器可查。

## ADR-008 测试：自写 TestRunner，不引 JUnit

**背景**：无构建工具，JUnit 需手动配 classpath。
**选择**：`TestRunner` 主类分组跑用例（合法/边界/错误注入），输出通过-失败表，失败即打印期望与实际。
**代价**：无 IDE 集成；换来的是零依赖、表格可截图进报告。

## ADR-009 词法/语法职责边界：词法只切词，结构合法性归语法

**背景**：`1.2.3`、`1..2` 这类输入，词法层既能切成两个合法数字（`NUM(1.2)` `NUM(.3)`），也能直接判词法错误。
**选择**：词法层只做"最长匹配切出合法记号"——`1.`、`.2`、`.5` 都算合法数字；两个数字相邻属于**结构错误**，由 `Parser` 报 `[语法错误] …期望运算符或结束，实际读到数字`。
**代价**：错误类别是 SYNTAX 而非 LEX，报告里要写清这条分界；换来的是词法器保持纯粹（无 lookahead、无上下文），与教材"词法/语法两阶段"一致，也让错误定位落在真正出错的那个数字上。
**连带责任**：`Parser` 必须能报出"数字接数字"这类错误（Day 05 验收项）。
